# Template Gaya Jawaban Mahasiswa Indonesia

Panduan memilih struktur penulisan sesuai JENIS tugas. Jangan pakai satu gaya
untuk semua tugas — dosen mengenali jawaban yang "formatnya salah".


---

## Cara pakai

1. Identifikasi jenis tugas dari soal (diskusi? praktikum? esai? laporan?)
2. Ambil template yang cocok di bawah, ikuti struktur & gayanya
3. Sesuaikan panjang dengan bobot soal (poin soal = perkiraan panjang jawaban)

---


---

## T1. Jawaban Diskusi / Q&A singkat (chat, WA, forum kelas)

```
Nomor/Pertanyaan (copy singkat atau nomor saja)

Jawaban 2-5 kalimat, langsung ke inti.
Boleh 1 contoh konkret atau angka.
Tanpa kesimpulan, tanpa pembuka "Menurut saya secara umum..."
```

Ciri mahasiswa: jawaban pertama biasanya paling panjang, sisanya makin pendek.
Boleh ada "kayak", "gitu", tapi jangan berlebihan di konteks formal.

---


---

## T2. Jawaban Latihan/Soal bernomor (kumpulan soal)

```
[Nomor soal]
Jawaban pendek. Point langsung. Tidak menulis ulang soal.
Kalau soal minta tabel → tabel. Kalau minta uraian → 1 paragraf.
Rumus ditulis: nilai = rumus yang diisi angka = hasil.
```

Ciri mahasiswa: tidak ada kata pengantar antar nomor. Nomor 1 panjang,
nomor 5 mungkin cuma 2 baris. Blok rumus sejajar dengan tanda `=`.

---


---

## T3. Laporan Praktikum / Lab (paling sering dipakai)

```
Identitas (nama, NIM, kelas/tanggal) — tanpa halaman sampul untuk tugas mingguan.

Catatan Teori / Jawaban pertanyaan teori
Praktikum:
  - Alat & bahan / data yang dipakai
  - Langkah kerja (kalimat biasa, bukan step-header)
  - Hasil & pembahasan per soal (a), (b), (c)...
Kesimpulan: 2-4 poin, terkait langsung hasil praktikum.
```

Larangan: BAB I/V, sampul, Daftar Pustaka (kecuali diminta),
"Tabel 4.1 ber-caption" untuk tugas mingguan.

---


---

## T4. Esai / Makalah Pendek

```
Pembuka: definisi/konteks masalah, 1 paragraf. Tanpa "Pendahuluan" sebagai judul
untuk esai < 5 halaman.
Isi: 2-4 bagian bernada (bukan nomor BAB), argumentasi + contoh nyata.
Penutup: rangkum posisi penulis + 1 implikasi. Tanpa "masa depan cerah".
```

Sumber: jika menyebut data/studi, sebutkan yang spesifik (nama, tahun).
Jangan daftar 10 referensi untuk esai 3 halaman.

---


---

## T5. Resume / Ringkasan Materi

```
Judul materi + nama.
Poin-poin per sub-materi, campuran bullet & kalimat pendek.
Boleh ada tabel perbandingan atau langkah bernomor.
Panjang: 1-2 halaman. Kalau lebih, dosen tahu itu copy-paste.
```

---


---

## T6. Kode Program (lampiran tugas pemrograman)

```
Kode dijelasin per bagian, bukan semua sekali:
1. Tampilkan kelas/struktur utama → jelaskan 1-2 kalimat
2. Tampilkan hasil eksekusi ASLI (bukan kutipan) dalam blok output
3. Analisis singkat: kenapa hasilnya begitu, sesuai teori atau tidak
```

Jangan tulis ulang seluruh kode jika sudah >100 baris; potong bagian inti +
sebutkan "kode lengkap di lampiran/file".

---


---

## T7. Makalah (BAB I-III)

```
Sampul (logo + judul + nama/NIM + prodi + tahun)
Kata Pengantar -> Daftar Isi
BAB I PENDAHULUAN: 1.1 Latar Belakang, 1.2 Rumusan Masalah, 1.3 Tujuan
BAB II PEMBAHASAN: sub-bab 2.1, 2.2, ... per topik
BAB III PENUTUP: 3.1 Kesimpulan, 3.2 Saran
Daftar Pustaka (5-10 sumber, urut abjad)
```

Font TNR 12pt, spasi 1.5, margin 4-4-3-3 cm (kiri 4 cm, atas 4 cm, kanan 3 cm, bawah 3 cm), halaman romawi di bagian awal.
5-15 halaman. Makalah TANPA BAB itu salah format — ini yang membedakannya
dari tugas mingguan.


---

## T8. Skripsi / Tugas Akhir (BAB I-V)

```
Bagian awal (romawi i, ii...): Halaman judul -> Lembar persetujuan ->
Abstrak (ID+EN) -> Kata Pengantar -> Daftar Isi/Tabel/Gambar
BAB I PENDAHULUAN (latar belakang, rumusan, tujuan, manfaat, batasan)
BAB II TINJAUAN PUSTAKA (teori, penelitian terdahulu, kerangka pikir)
BAB III METODE PENELITIAN (jenis, populasi/sampel, instrumen, analisis)
BAB IV HASIL DAN PEMBAHASAN
BAB V KESIMPULAN DAN SARAN
Daftar Pustaka -> Lampiran
```

TNR 12pt, spasi 2.0 (isi) / 1.0 (tabel, kutipan panjang), margin 4-4-3-3 cm.
Rumusan masalah <-> tujuan <-> kesimpulan WAJIB sejajar satu-satu.
Selalu ikut pedoman resmi kampus kalau ada — tiap kampus beda detail.


---

## T9. Proposal Penelitian

```
Sampul -> BAB I Pendahuluan -> BAB II Tinjauan Pustaka ->
BAB III Metode Penelitian (desain, populasi/sampel, instrumen, analisis)
-> Jadwal Penelitian (tabel bulan x kegiatan) -> Daftar Pustaka
```

Format skripsi TANPA BAB IV/V — penelitian belum jalan, jadi tidak ada
hasil dan kesimpulan. Metode harus paling detail; itu yang dinilai.


---

## T10. Artikel Jurnal (IMRAD)

```
Judul -> Nama (tanpa gelar) + afiliasi -> Abstrak 150-250 kata (ID+EN)
+ 3-5 kata kunci -> 1. Pendahuluan (state of the art + kebaruan) ->
2. Metode -> 3. Hasil dan Pembahasan -> 4. Kesimpulan -> Daftar Pustaka
```

Sub-judul pakai ANGKA (1., 2., 3.), BUKAN "BAB I". TNR 10-12pt, spasi
1.15-1.5, maksimal sekitar 7 halaman, referensi minimal 15, sitasi [1, 5]
gaya Vancouver (urut kemunculan). Tanpa kata pengantar & daftar isi.


---

## T11. Laporan Magang / KKN

```
Sampul -> Lembar persetujuan -> Kata Pengantar -> Daftar Isi
BAB I Pendahuluan (latar, tujuan, waktu/tempat)
BAB II Gambaran Umum (profil perusahaan/desa)
BAB III Kegiatan (per tanggung jawab, BUKAN hari-per-hari)
BAB IV Pembahasan (yang dipelajari, kendala, solusi)
BAB V Penutup -> Lampiran (log book bertanda tangan, foto)
```

Mirip skripsi ringan. Log book bertanda tangan pembimbing lapangan sering
jadi syarat nilai.


---

## T12. Tugas Sekolah (SMP/SMA: laporan pengamatan, resume, makalah sekolah)

```
Laporan pengamatan/pengalaman (paling umum):
  Identitas: Nama, Kelas, No. Absen, Nama guru/mapel, Tanggal (kadang kop sekolah)
  Pendahuluan: 1 paragraf, apa yang diamati/dilakukan & kenapa
  Isi: kronologis atau per poin pengamatan; detail konkret (tempat, jam, siapa)
  Penutup: kesan + simpulan singkat, boleh 1 kritik/saran pribadi

Resume/rangkuman materi:
  Identitas + judul materi
  Poin per bab/sub-bab buku paket, campuran bullet & kalimat
  1-2 halaman, tulis tangan = seimbang rapi, bukan sempurna

Makalah sekolah:
  Sampul/kop sekolah, KATA PENGANTAR (wajib di sekolah: puji syukur,
  tujuan, ucapan terima kasih ke guru, "penulis menyadari masih banyak
  kekurangan..."), Daftar Isi
  BAB I Pendahuluan (Latar Belakang + Rumusan Masalah), BAB II Pembahasan,
  BAB III Penutup (Kesimpulan + Saran), Daftar Pustaka singkat
```

Ciri siswa asli: kata pengantar pakai frasa baku yang persis sama di semua
sekolah ("Demikian makalah ini disusun..."), penutup mengandung opini pribadi
("menurut saya bagian paling menarik adalah..."), dan ada ketidakkonsistenan
kecil format antar halaman. Laporan terlalu rapi + tanpa opini = dicurigai.

## T13. Tugas Teori + Simulasi Komputasi (catatan teori & angka, bukan laporan praktikum)

Untuk tugas matkul terapan (stokastik, statistika komputasi, ML) yang
minta jawaban teori per soal DITAMBAH simulasi/angka:

```
Header ringkas: JUDUL TUGAS + nama · NIM (satu baris, tanpa sampul)
BAGIAN 1: PEMBAHASAN TEORI (per soal bernomor 1, 2, 3...)
  - Jawaban langsung per soal, definisi disisipkan dalam kalimat
    (bukan kamus istilah), contoh konkret milik sendiri (server, antrean,
    toko online — bukan contoh buku yang sama dengan teman sekelas).
  - Soal analisis kasus: kasus → kenapa asumsi gugur → solusi teknis
    (state yang diperluas, rumus pendek). Solusi ditulis konkret, bukan
    "gunakan model yang lebih baik".
BAGIAN 2: SIMULASI / KOMPUTASI
  - 1 baris deskripsi eksperimen: jumlah lintasan/iterasi, langkah,
    library, seed, parameter (p = 0,5 dsb). Seed boleh NIM sendiri.
  - Kode inti (potongan yang jalan, bukan skrip penuh)
  - Output eksekusi ASLI + tabel simulasi vs teori (rata-rata, ragam,
    nilai teoretis) — angka dari run nyata, TIDAK dikarang meski
    "seharusnya" mendekati teori.
  - Gambar plot dengan caption bernomor (Gambar 1. ...)
  - Analisis hasil: angka → cocok/tidak dengan teori → jelaskan MENGAPA
    lewat sifat matematis (Var(Sn)=n, ketiadaan mean reversion, dst).
```

Ciri mahasiswa asli di tipe tugas ini:
- Panjang jawaban teori TIDAK seragam antar nomor (soal yang dia paham
  panjang, yang gak yakin pendek).
- Angka simulasi sedikit menyimpang dari teori dan disebut wajar dengan
  alasannya ("galat baku ±√(n/N)", "selisih di bawah 1 persen kecuali n=100
  karena sampel 200"), bukan cocok persis 100%.
- Analisis akhir menjawab pertanyaan soal (mis. "kenapa tidak stasioner"),
  bukan merangkum ulang seluruh tugas.
- Pembuktian pendek konkrit (bandingkan P(...) pada dua state berbeda)
  lebih baik daripada uraian formal panjang.
- Red flag versi tipe ini: bold mekanis di awal tiap penjelasan
  (**Pertama**, **Kedua**), kolom "Keterangan Evaluasi" berisi kalimat
  generik per baris tabel, dan dua contoh aplikasi berparalel sempurna.

Aturan rendering (hasil nyata: PDF bagus rusak jadi gak kredibel):
- Tabel WAJIB tabel Markdown asli dengan header + garis `|---|`.
  DILARANG memakai heading (###) sebagai baris tabel — PDF converter
  merender angka jadi sub-judul dan hasilnya seperti parse error.
- Kode WAJIB dalam fenced code block (```python ... ```). Kode yang
  ditulis sebagai teks biasa akan di-reflow jadi satu paragraf acak
  saat render (kasus nyata: `import numpy ... rng.choice(...)` jadi
  kalimat kacau).
- Persamaan ditulis dalam notasi ASCII yang tidak rusak saat konversi:
  `P(X_{t+1} | X_t)`, `Var(S_n) = n`, `m^1000`. Hindari LaTeX penuh
  ($...$, \frac) di pipeline yang tidak dirender KaTeX; kalau pipeline
  mendukung LaTeX, tetap tes hasil render sebelum kirim.
- Jangan memotong kalimat di tengah baris/frasa matematis; angka
  subscript jangan terpisah dari induknya.
- Struktur sumber yang terbukti rapi (target):
  H1 judul tugas → baris "Mata kuliah Nama · NIM" → H2 per soal
  bernomor → paragraf isi → H2 "BAGIAN B: KOMPUTASI" → 1 paragraf
  setup eksperimen → tabel Markdown → analisis → H2 "Lampiran: Kode"
  berisi fenced block → caption Gambar sebagai teks italic setelah
  gambar.
- Setelah generate PDF, WAJIB self-check: baca ulang teks PDF hasil
  render, pastikan (a) tabel jadi tabel, (b) kode tetap per baris,
  (c) semua persamaan utuh, (d) tidak ada kalimat kepotong. Kalau
  rusak, perbaiki sumber Markdown bukan PDF-nya.
- Tampilan: pakai `references/render-style.css` — kode ter-highlight
  ala VS Code (dark theme, Pygments/hljs), blok output eksekusi
  dibedakan dari kode (latar terminal hijau), dan tabel bergaris rapi
  ala Excel (header biru, zebra stripes, caption bawah). Kode di Markdown
  ditulis ```python, output ```output, biar CSS-nya nembak tepat.

## Red flags "bukan gaya mahasiswa" (cek sebelum submit)

- Struktur terlalu seragam (semua jawaban panjangnya mirip)
- Setiap bagian dibuka kalimat pengantar ("Berikut adalah...", "Secara umum...")
- Kesimpulan yang mengulang semua poin
- Header bersarang 3 level untuk tugas 2 halaman
- Tabel di mana-mana padahal soal tidak minta
- Bahasa terlalu buku di konteks santai (atau sebaliknya)


---

## Kalibrasi suara

- Tanya user dosen siapa / mata kuliah apa kalau ada contoh tugas yang diterima
- Cocokkan tingkat formal: praktikum → formal kaku dikit; diskusi WA → santai
- Ketidaksempurnaan kecil (pilihan kata kurang konsisten, kalimat pendek mendadak)
  itu NORMAL dan harus dipertahankan
